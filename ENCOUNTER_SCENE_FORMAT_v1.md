# Общая сцена боя · формат v1

Статус: **РАБОЧЕЕ · готово к плейтесту**. Локальный пакет от 13.11.2026 поверх принятой библиотеки NPC. Публикация на GitHub Pages не выполнена. Этот контракт не устанавливает новых игровых правил.

## Владельцы

- `assets/encounter-scene.js` — формат сцены, проверка, атомарные команды и книга сохранённых боёв.
- `assets/encounter-draft.js` — черновик и резервная копия каждой вкладки.
- `assets/encounter-migrate.js` — явный односторонний перенос прежнего NPC v56 и сцены монстров v1.
- `assets/encounter-ui.js`, `encounter.html`, `assets/encounter.css` — общий рабочий экран.
- `assets/github-store.js`, `assets/shared-library-ui.js` — существующее подключение GitHub; контракт библиотеки описан в [SHARED_LIBRARY_FORMAT_v1.md](SHARED_LIBRARY_FORMAT_v1.md).
- `assets/bestiary-data.js` — единый источник 18 исходных статблоков для прежнего и общего боевых экранов. Извлечён без изменения данных из `monsters-battle.html`; аномальные наборы и Monster Manual остаются в своих модулях.

## Сцена и участники

Документ содержит `format: wot-encounter`, `version: 1`, постоянный `sceneId`, имя и даты, `actors`, очередь `order`, `activeId`, `selectedId`, `round`, `running`, `turnSerial`, последние 100 записей `log`. Очередь состоит из ID участников с заданной инициативой. Выбор карточки независим от текущего хода; начало, следующий ход и ручная коррекция открывают карточку действующего участника. 0 ОЗ не удаляет участника. Пауза блокирует следующий ход; изменение инициативы сохраняет текущего участника начатого боя. При равной инициативе сохраняется порядок предыдущей очереди.

Каждый участник имеет уникальный UUID, вид `npc`, `monster` или `manual`, стабильный номер копии, ссылку на каталог/ID/редакцию источника, полный снимок карточки `snapshot`, отдельное состояние `state`, эффективный `maxHp` и инициативу. Изменение или архивирование источника не меняет уже созданный снимок. Первая копия может носить исходное имя; последующие получают свободный номер. Имена существующих участников автоматически не меняются.

Сохраняются родные состояния: NPC — `npc-state-v56` (`curHp`, массив `conditions`, ячейки `slots` и остальные поля); монстр — `monster-state-v1` (`hp`, карта `conds`, `phase`, `roll`, `bleach` и остальные поля); ручной участник — `manual-v1`, без придуманного максимума ОЗ. Дополнительные счётчики — `manualResources` с `name`, `total`, `used`; заметки — `sceneNotes`. Неотображаемые родные поля проходят JSON-перенос без отбрасывания. Показанные числовые ресурсы валидируются, а не исправляются молча.

«Создать копию боя» выдаёт новый ID сцены и всех участников, переназначает очередь/выбор/ход и сохраняет текущие хиты, ресурсы и раунд. Это также путь сохранения независимой версии после конфликта.

## GitHub

По умолчанию: `DenVks/wot-hierarchy-site`, ветка `wot-data`, файл `wot-data/encounters.json`. Книга: `format: wot-encounter-book`, `version: 1`, массив `records`; запись содержит `sceneId`, `revision`, `archived`, полный `scene`. До 100 записей, 1000 участников на сцену; общий транспорт ограничивает документ 8 МиБ. Архивный флаг предусмотрен контрактом; отдельного интерфейса архивирования боёв пока нет.

Чтение/запись используют общее подключение библиотеки. Перед сохранением загружается актуальная книга; проверяются revision открытой сцены и SHA файла GitHub. Сохранение на устаревшей основе отклоняется. Подтверждённой считается только успешная запись API. Ошибка оставляет черновик в своей вкладке. Другие бои не перезаписываются старым списком. Неизвестный формат, повреждение, ошибка доступа или сети не превращаются в пустую книгу. Отсутствующие ветка и документ создаются через общий транспорт только при наличии права записи. Default branch защищена от записи данных.

Публичная ветка содержит публичные данные; пароль сайта не скрывает файлы GitHub. Ключ вводится в существующем окне подключения, не попадает в карточки, URL, экспорт и код. По умолчанию действует до обновления страницы; отдельный флажок сохраняет его в сессии вкладки. Пользователь может выбрать приватный репозиторий данных в том же интерфейсе.

## Черновик, импорт и перенос

Каждая обычная независимая вкладка получает session ID и свой локальный ключ `wot.encounterScene.draft.v1.tab.<id>` с собственной `.backup`. Общий `wot.encounterScene.draft.v1` — только последний снимок для старта новой вкладки/перехода из генератора. Перезагрузка своей вкладки восстанавливает собственный черновик, даже если другая вкладка изменила тот же бой. Дублирование вкладки браузером с копированием sessionStorage отдельно не проверено.

Перед заменой сцены текущий снимок резервируется. Ошибка записи резерва прекращает замену. Повреждённый черновик не перезаписывается автоматически. Без доступа к хранилищу страницы бой может существовать в памяти с видимой ошибкой сохранения. Локальный черновик не заменяет GitHub для доступа с другого компьютера.

Импорт сначала разбирает и проверяет весь JSON (до 8 МиБ), затем показывает имя и число участников и требует явного подтверждения. Поддерживаются общая сцена v1 и прежний экспорт `wot-monster-scene` v1 с установленным набором бестиария. Неизвестные версии отвергаются. У импортированного JSON нет подтверждённой revision GitHub: при совпадении ID с сохранённым боем требуется открыть его актуальную версию или создать независимую копию.

Кнопки переноса читают `wot_dm_npc_state_v56` или `wot.monsterScene.v1` только на текущем origin браузера. В новую сцену входят участники очереди и созданные боевые копии; при отсутствии такого состава — все сохранённые карточки. Исходник целиком хранится в `legacy.payload`, включая не включённые в состав строки и прежние журналы. Исходный ключ не изменяется и не удаляется. Новая общая сцена резервируется до замены. Монстры проверяются прежним валидатором; сохраняются профиль защиты, происхождение правок, черты среды, состояния, фаза, броски и метки. Для NPC сохраняется полный родной state, включая применённый бонус максимума ОЗ, эликсиры и дополнительные поля. Отсутствующая карточка участника или неподдерживаемое состояние вызывают отказ без замены.

Переносы заменяют текущую общую сцену, а не автоматически объединяют две прежние очереди. Обратная миграция из общей сцены в старые инструменты не заявлена.

## Пользовательский путь

1. В генераторе создать или отредактировать NPC и сохранить в GitHub.
2. «Сохранить и добавить в общую сцену» либо «В общую сцену» у записи открывает `encounter.html?addNpc=<libraryId>&transfer=<uuid>`.
3. После загрузки библиотеки нужная карточка добавляется в текущий черновик как независимый участник. Одноразовый transfer предотвращает повтор после перезагрузки; затем параметры убираются из URL. Повторный осознанный переход создаёт следующую копию.
4. Через каталог добавить монстров, другие NPC или ручного участника, задать инициативу и начать бой. У каждого свои хиты/состояния/ресурсы.
5. «Сохранить бой в GitHub». На другом компьютере открыть этот сайт, выбрать то же хранилище, загрузить список боёв и открыть нужный. Для записи подключить ключ на этом компьютере.

## Границы автоматизации

Общий экран предоставляет базовые действия смешанного боя: очередь/ход/раунд, хиты, состояния, броски, ячейки NPC, кости превосходства при наличии, легендарный ресурс монстра, собственные счётчики, заметки и полные сохранённые тексты карточки. Броски инициативы имеют отдельные обычный режим, преимущество и помеху; режим выбирает Мастер. При неизвестном модификаторе требуется ручной итог.

Кнопки урона показывают полную распознанную формулу, включая несколько явно записанных типов урона. Неоднозначные формулы, альтернативы и пояснения с равенствами не обрезаются: итог вводится вручную. Сопротивления, спасброски, критические попадания, автоматический расход действия, концентрация и игровые последствия не применяются автоматически.

Переключение фазы отмечает её состояние и показывает правило. Числовые бонусы из произвольного текста фазы применяет Мастер. Полное автоматическое воспроизведение прежних профильных экранов (предметы, боевые формы, таланты, эликсиры, тактические подсказки, отдых и индивидуальные классовые обработчики) в этом пакете не реализовано. Их данные сохраняются; действующие подробные инструменты остаются в меню. Поэтому этот пакет — **готово к плейтесту общего боя**, а не полная замена всех возможностей двух старых инструментов.
